**Goal:** Port Mark III's `apps/desktop` into this workspace and ship a stable, polished, fully navigable UI (no backend) launchable via a `.bat`/`.vbs` launcher for bug-by-bug user testing.

**Architecture:** Electron (frameless) + React 18 + TypeScript + Vite + Tailwind + Three.js sphere, copied from `I:\Code Shit\OpenCode\Projects\Jarvis Mark III\apps\desktop` minus `node_modules/` and `dist/`, then fixed bug-by-bug. **Tech Stack:** Electron 42, Vite 6, React 18, three ^0.170, CodeMirror 6 (text editor), custom tokenizer code editor, Tailwind 3.

**Spec:** `PROJECT_SUMMARY.md` §4A (UI phase) — dark theme, blue/cyan accents, sphere, per-tab pages, customizable tabs/widgets, no overlapping HUD elements.

## Global Constraints

- Port 11711 stays reserved for the future backend; this phase must not bind to it (log wins, not crashes, when WebSocket fails).
- Keep the Mark III visual language: `jarvis` Tailwind palette (`bg #0a0f1a`, `surface #111827`, `blue #2763d1`, `cyan #00d4ff`), frameless window, HUD overlays.
- Every fix lands as its own commit (one bug = one commit) so the user can bisect regressions.
- No new runtime deps for this phase except what's already in Mark III's package.json.
- Windows-first: launchers are `.bat`/`.vbs` like earlier marks; keep `%~dp0` path handling.

## Review Focus

- **Overlap:** with sidebar open (left, 256px) AND chat open, chat panel must not render under the sidebar; same for file panel on the right. Test: open both, check chat input fully visible/clickable.
- **All tabs usable:** every tab in TabBar renders real content or an explicit empty-state — never a blank screen. Test: cycle Chat→Code→News→Stocks→a custom tab.
- **Icons render:** every built-in tab shows its emoji; settings rows show palette colors that exist (e.g. no `jarvis-green` silently missing → rename to `success`).
- **Persistence:** sidebar/chat open state, active tab, sessions (rename/delete), widgets, MCP/webhook lists survive an app restart from the launcher. Test: relaunch and check state.
- **Graceful no-backend:** app stays usable with the backend absent — WS retries quietly, sessions/widgets still work from local state.
